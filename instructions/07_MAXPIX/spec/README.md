# MAXPIX 指令規格與編碼（CP3）

## 指令語意

指令將 `rs1` 視為四個無號 8-bit 像素：

```text
b0 = rs1[7:0]
b1 = rs1[15:8]
b2 = rs1[23:16]
b3 = rs1[31:24]
rd = max(b0, b1, b2, b3)
```

結果範圍是 0–255，寫入 `rd` 的高 24 位為 0。`rs2` 不參與運算，編碼時固定為 `x0`，以確保只有一種 canonical encoding。

## 虛擬碼

```text
u8 b0 = rs1[7:0]
u8 b1 = rs1[15:8]
u8 b2 = rs1[23:16]
u8 b3 = rs1[31:24]
rd = zero_extend_32(max_unsigned(b0, b1, b2, b3))
```

## R-type 編碼欄位

| 欄位 | 位元 | 本候選編碼 | 說明 |
|---|---:|---:|---|
| `funct7` | `[31:25]` | `0000000` | 候選值，待教師分配確認 |
| `rs2` | `[24:20]` | `00000` (`x0`) | 保留，不使用 |
| `rs1` | `[19:15]` | 來源暫存器 | 四個 packed pixels |
| `funct3` | `[14:12]` | `011` | 候選值，待教師分配確認 |
| `rd` | `[11:7]` | 目的暫存器 | 零延伸後的最大值 |
| `opcode` | `[6:0]` | `0001011` (`0x0B`) | custom-0 |

**編碼狀態：**目前倉庫中找不到教師對 MAXPIX 的 `funct3`、`funct7` 分配。為完成範例機器碼與欄位分析，以下暫以 `funct7=0`、`funct3=3` 作候選值；這不是正式分配，送交前須以教師公告值替換。若正式值不同，機器碼也會不同。

## 範例向量與候選機器碼

以下均使用 `rd=a0` (`x10`)、`rs1=a0` (`x10`)、保留欄位 `rs2=x0`。三個範例的指令機器碼相同，因為輸入資料值在執行時才由 `a0` 提供，並不編入指令字。

| 輸入 `a0` | `b3:b2:b1:b0` | 預期 `a0` | 候選機器碼 |
|---:|---|---:|---:|
| `0x0A1E2805` | `0A:1E:28:05` | `40` (`0x28`) | `0x0005350B` |
| `0x00000000` | `00:00:00:00` | `0` | `0x0005350B` |
| `0xFF000001` | `FF:00:00:01` | `255` (`0xFF`) | `0x0005350B` |

解碼候選機器碼 `0x0005350B`：`funct7=0000000`、`rs2=00000`、`rs1=01010`、`funct3=011`、`rd=01010`、`opcode=0001011`。第三例覆蓋最大 unsigned byte `0xFF` 的邊界情況。

## 指令數比較（靜態）

比較範圍是 MAXPIX 函式本體，不計 caller、測試 harness 和啟動程式。RV32IM baseline 依 [`../rv32im/maxpix.S`](../rv32im/maxpix.S) 的 pseudo 展開統計；自訂指令版本以一條 `MAXPIX rd, rs1` 取代整段運算。

| 實作 | 靜態指令數 | 說明 |
|---|---:|---|
| RV32IM baseline | 18 | `mv` 展開為 `addi`，`ret` 展開為 `jalr` |
| 單一自訂指令 | 1 | 假設處理器已實作並可辨識 MAXPIX |
| 差異 | 減少 17（約 94.4%） | `(18 - 1) / 18` |

以上是指令數比較，未代表 CPI 或執行時間比較；本 CP 不要求 cycle 數。
