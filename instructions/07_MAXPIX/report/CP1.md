# CP1：MAXPIX C baseline

## 1. 本次目標

以 C 實作 MAXPIX 參考函式，並用至少 10 組輸入和預期輸出驗證功能。

## 2. 設計內容

`c_baseline/maxpix.c` 接收一個 `uint32_t`，將其中四個 byte 以位移和 `0xff` 遮罩取出。最低有效 byte 為 `b0`，最高有效 byte 為 `b3`。程式先比較 `(b0,b1)` 與 `(b2,b3)`，再比較兩組較大值，合計三次比較，回傳範圍為 0–255。

像素以無號數值比較，避免 `0x80`–`0xff` 被解讀成負數。`c_baseline/test_maxpix.c` 提供自動測試；`tests/vectors.csv` 列出輸入、預期輸出和測試目的。

### 設計決策：5 Whys

1. 為什麼先拆成四個 byte？因為規格把 `rs1` 定義成四個獨立的 8-bit 像素。
2. 為什麼要用位移和 `0xff`？位移把目標 byte 移到最低 8 位，遮罩可去掉其他 byte。
3. 為什麼像素用無號整數比較？像素值範圍是 0–255，`0x80`–`0xff` 不能被當成負數。
4. 為什麼分兩組求最大再比較？四個值可以用三次比較完成最大值選取，步驟清楚且容易對照規格。
5. 為什麼用 `uint32_t` 保存結果？它能表示完整 0–255 範圍，並保證回傳值高 24 位為 0。

## 3. 結果與分析

使用 Zig 0.16.0 的 C 編譯器介面，以 `-std=c11 -Wall -Wextra -Werror` 編譯 `maxpix.c` 和 `test_maxpix.c`；編譯成功，12 組測試全部通過。

| # | 輸入 | 預期輸出 | 測試目的 |
|---:|---:|---:|---|
| 1 | `0x0A1E2805` | 40 | 作業範例 |
| 2 | `0x00000000` | 0 | 下界、全零 |
| 3 | `0xFF000001` | 255 | 上界、最高 byte 為最大值 |
| 4 | `0x01020304` | 4 | byte 遞增排列 |
| 5 | `0x04030201` | 4 | byte 遞減排列 |
| 6 | `0x7F807F80` | 128 | 127/128 無號分界 |
| 7 | `0x80808080` | 128 | 四個 byte 相等 |
| 8 | `0xFFFFFFFF` | 255 | 四個 byte 均為最大值 |
| 9 | `0x0100FF00` | 255 | 最大值位於 byte 1 |
| 10 | `0x000000FF` | 255 | 最大值位於 byte 0 |
| 11 | `0x01010101` | 1 | 小值且四個 byte 相等 |
| 12 | `0x00010000` | 1 | 最大值位於 byte 2 |

實際輸出與預期輸出逐筆相同，摘要為 `12/12 tests passed`。測試檔的預期值也與 `tests/vectors.csv` 一致。

## 4. 遭遇的問題與解法

起初環境沒有 `gcc` 或 `clang`，因此無法直接編譯 C 程式。確認可用 Python 後，安裝 Zig 0.16.0，使用 `py -3 -m ziglang cc` 編譯；加上 `-Wall -Wextra -Werror` 後成功建置，並執行 12 組測試全數通過。

## 5. 白話說明

一個 32 位元輸入可以看成四個 8 位元像素排在一起。我們用位移和遮罩逐一取出四個數字，先兩兩比較，再比較兩組勝出的數字。最大值可能是 255，所以像素要當無號數看待；否則最高位為 1 的像素會被誤當成負數。
