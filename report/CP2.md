# CP2：MAXPIX RV32IM 實作

## 1. 本次目標

以 RV32IM 組合語言實作四個 packed unsigned byte 的最大值，並統計函式靜態與動態指令數及分支數。

## 2. 設計內容

函式 `maxpix_rv32im` 依 RISC-V ILP32 呼叫慣例接收 `a0`，並在 `a0` 回傳結果。先以移位和遮罩依序取出四個 8-bit 像素，使用 `sltu` 對目前最大值與下一像素做無號比較。若新像素較大，更新目前最大值。程式未使用 M 擴充指令，使用的都是 RV32I 指令。

統計只涵蓋被呼叫函式本體，並將 `mv`、`ret` 分別按 `addi`、`jalr` 展開。靜態指令數為 18，含 3 條條件分支 `beqz`；函式返回另有 1 條 `jalr`。動態指令數為 15–18，3 條條件分支每次呼叫都執行，taken 數依輸入而定。每當新像素成為最大值，動態數增加 1 條 `mv`。

## 3. 結果與分析

| 項目 | 數量 |
|---|---:|
| 靜態指令數（含 pseudo 展開） | 18 |
| 靜態條件分支數 | 3 |
| 返回指令 | 1 條 `jalr` |
| 動態指令數 | 15–18 |
| 動態條件分支執行數 | 每次 3 |

動態統計依程式控制流程對 `tests/vectors.csv` 的 12 組測資計算；各組明細列於 [`instructions/07_MAXPIX/rv32im/README.md`](../instructions/07_MAXPIX/rv32im/README.md)。統計不含 caller、測試 harness 和啟動程式，也未以模擬器 trace 驗證。

## 4. 遭遇的問題與解法

像素是 unsigned byte，若用 signed 比較，最高位為 1 的像素（例如 255）可能被當成負數，導致結果錯誤。因此使用 `sltu`，並在每次比較前遮罩至 8 位，確保比較對象是 0 到 255。

## 5. 白話說明

把 32 位元輸入切成四個 8 位元數字，先拿第一個當暫時冠軍。接著每次拿下一個數字來比；如果它比較大，就換它當冠軍。四個都比完後，冠軍就是答案。因為每個像素都只看成 0 到 255 的正整數，組合語言使用無號比較。
